## 1. 현재 운영 규칙 — `U25_L1_POP35`

```
후보 : 전 조합 8,145,060개 중 추정 인기도 하위 35% (2,850,771개)
제약 : 모든 줄 쌍 공통 번호 <= 1,  번호당 사용 <= 5회
시드 : round*10000+2026 부터 60개 탐색, 5등↑ 커버리지 최대 채택 (동률 시 큰 시드)
실패 : 오류로 중단. 시드·제약을 완화하지 않는다.
난수 : numpy default_rng (PCG64), 조합 배열은 itertools.combinations 사전식 순서
```

**시드 탐색은 사후선택이 아니다.** 커버리지는 당첨번호를 전혀 참조하지 않는
결정론적 조합 성질이며 추첨 전에 계산된다. 과거 성적 좋았던 시드를 고르는 것과
근본적으로 다르다. 이 구분을 반드시 유지하라.

**컷 35%의 근거**: 하위 30%는 후보가 고번호에 몰려 "번호당 5회" 제약과 충돌해
20시드 중 15개만 생성 성공했다. 35%는 20/20 성공하는 가장 조인 값이다.

## 3. 구매 인기도 — 검증 경과

### 3.1 왜 5등을 쓰는가

1등 당첨게임 수는 회차당 약 10건이라 노이즈가 신호를 덮는다. 같은 40회차에서 r=+0.067.
**5등은 약 250만 건**이라 측정 정밀도가 압도적이다(포아송 상대오차 0.06%).
단, **회귀의 독립 관측 단위는 회차이지 티켓이 아니다.**

### 3.2 판매액 복원

```
S = 16*B2 + 2*(50,000*W4 + 5,000*W5)       B2 = 2등 1게임 금액 x 2등 게임수
```
실측 판매액과 대조 시 **원 단위 반올림으로 최대 1,000원 차이**(상대차 ~1e-8).
"오차 0%"가 아니라 "반올림 수준"이 정확한 표현이다.

### 3.3 사전 등록된 확증 검정 (40회, 1184~1223)

`5등배수 = α + β·(12이하 개수)`:
**β = +0.02946 ± 0.00608, t = +4.849, 단측 p = 0.00001**

### 3.4 459회 확대 (784~1243)

| 특징 | t |
|---|---|
| n_le12 | **+16.36** |
| 번호합 | **−15.88** |

저번호 관련 3개가 압도적. **특정 특징을 골라서 생긴 신호가 아니다.**

### 3.5 번호별 인기도 직접 추정 — 현재 근거

`Z_t = α + Σ_j γ_j·1(번호 j 추첨)` 릿지(λ=1), 459회.

| 모형 | 시간분할 검증 R² |
|---|---|
| n_le12 단독 | 0.3828 |
| 번호합 단독 | 0.3717 |
| **번호별 릿지** | **0.6800** |

**전향 검증** (γ를 784~1143 359회로 적합 → 1144~1243 100회 검증):
인기도 점수 → 5등배수 회귀 **r = +0.852, t = +16.13, p = 2.5e-29**
하위 50% 통과회차 5등배수 0.9759 vs 탈락 1.0286 (**t = −7.50, p < 1e-5**)

**시대 안정성** (153회씩 3구간 독립 추정): 구간 간 γ 상관 **0.801 / 0.816 / 0.823**.
약 9년간 구매 선호 구조가 안정적이다.

### 3.7 남은 한계 — 반드시 함께 보고할 것

1. **5등 → 티켓 환산**은 감쇠계수 11/26과 곱셈적·균일 효과라는 모델 가정에 의존한다
2. **1~3등 전체 적용 불가**. 2등은 6개, 3등은 **228개** 조합에 분산되므로

## 6. 방법론 체크리스트

7라운드 상호검증에서 실제로 발생한 오류에 대응한다.

1. 정규화 분모가 측정 대상에 오염되지 않았는가 (2등 상금풀에는 4·5등 게임수가 들어간다 → 판매액 역산 사용)
2. 검정통계량의 참조분포가 추첨 구조를 반영하는가 (한 회차 6개는 비복원 → X²를 44/39배 하고 χ²₄₄와 비교. **자유도는 44 유지**)
3. 비선형 변환에 평균을 대입하지 않았는가 (E[1/(K+1)] ≠ 1/(E[K]+1))
4. 모의실험의 생성 가정을 실데이터 모먼트와 대조했는가 (K의 과산포는 Y의 변동계수가 아니다)
5. 임계값·특징을 자료를 보고 정했다면 그 자료의 p값을 쓰지 않았는가
6. 다수 설정을 볼 때 중첩을 반영한 공동 귀무분포로 평가했는가 (N개 설정 ≠ N번 독립 확인)
7. 검증 계획의 검정력을 먼저 계산했는가
8. 항등식과 기대값을 구분했는가 (319.5655원은 판매게임당 **기대** 배정재원)
9. 추정량을 결과를 본 뒤 고르지 않았는가
10. 신호가 안 보이면 측정 창문을 의심하라 (1등 n≈10 에서 안 보이던 것이 5등 n≈250만 에서 t=16)

## 7. 주장해도 되는 것과 안 되는 것

**된다**: 고정 25줄의 조합론적 확률, 커버리지, 2등↑ 상한 달성, 4·5등 고정분 기대값,

"적중률 N%"를 예측력으로 표현, 인기도 효과를 검증된 확정 금액으로 제시,
1,000원당 기대 당첨금이 어떤 방식으로도 500원 고정이라는 주장.

## 8. 주간 절차

1. 사용자가 당첨번호를 주면 회차를 확인하고 **직전 전달본만** 채점한다
2. 등수별 당첨게임 수를 받으면 `data/tier_winners_*.csv` 에 추가한다
3. 20회 이상 쌓이면 `estimate_popularity.py` 로 γ를 갱신하고 시간분할 검증을 다시 돌린다
4. `generate.py --round <t>` 로 다음 회차를 생성한다
5. 생성 후 `lotto_core.verify()` 로 불변 조건을 확인한다
6. **결과를 보고 시드·컷·제약을 바꾸지 않는다**
